# 🎵 File Upload Flow (Multer + ImageKit) — Complete Notes

---

## 🧠 1. Core Mental Model

```text
Client → Server → Multer → (RAM / Disk) → ImageKit → DB → Response
```

* File leaves user device immediately after upload starts
* Server owns the file during processing
* Database stores **URL**, NOT file

---

## 📦 2. Multer Storage Types

### 🔴 memoryStorage()

* Stores file in **RAM**
* Access via:

  ```js
  req.file.buffer
  ```
* ❌ Not good for large files
* ❌ Can crash server

---

### 🟢 diskStorage()

* Stores file in **server filesystem**
* Access via:

  ```js
  req.file.path
  req.file.filename
  ```
* ✅ Better for large files (audio/video)
* ⚠️ Must delete file after upload

---

## 📁 3. Upload Folder

* Create manually:

  ```bash
  mkdir uploads
  ```
* Location:

  ```text
  project-root/uploads/
  ```

---

## 🔁 4. Multer → ImageKit Flow

### Step-by-step:

1. Client sends:

   ```
   form-data:
   - file (File)
   - title (Text)
   ```

2. Multer processes:

   ```js
   req.file = {
     path,
     filename,
     originalname
   }
   ```

3. Upload to ImageKit:

   ```js
   const stream = fs.createReadStream(file.path);

   await imageKit.files.upload({
     file: stream,
     fileName: file.filename,
     folder: "/music"
   });
   ```

---

## ⚠️ 5. Buffer vs Stream vs Base64

| Method | Use         | Problem          |
| ------ | ----------- | ---------------- |
| Buffer | small files | can hang         |
| Base64 | quick fix   | slower, larger   |
| Stream | ✅ best      | production-ready |

👉 Always prefer **stream**

---

## 🧹 6. File Cleanup (VERY IMPORTANT)

After upload:

```js
await fs.unlink(req.file.path);
```

---

### Why?

* Prevent disk filling
* Avoid storage leaks

---

## ⚠️ 7. fs vs fs/promises

### ❌ Wrong

```js
const fs = require("fs");
await fs.unlink(path); // ❌ error
```

---

### ✅ Correct

```js
const fs = require("fs/promises");
await fs.unlink(path);
```

👉 MUST match:

```js
upload.single("file")
```

## 🔥 9. Common Errors & Fixes

### ❌ Unexpected field

→ field name mismatch
✔ fix: use `"file"`

---

### ❌ fileName missing

→ not passing `file.filename`
✔ fix:

```js
fileName: file.filename
```

---

### ❌ fs is not defined

→ forgot import
✔ fix:

```js
const fs = require("fs");
```

---

### ❌ unlink cb error

→ mixing async + callback
✔ fix:

```js
const fs = require("fs/promises");
```

---

### ❌ upload hanging

→ buffer issue
✔ fix:

```js
Readable.from(buffer) OR createReadStream(path)
```

| ----------- | ------ | ----------- |
| Storage     | RAM    | Server disk |
| Large files | ❌      | ✅           |
| Production  | ❌      | ✅           |

## 🚀 11. Production Architecture Levels

### 🥉 Basic

```
memoryStorage → upload
```

---

### 🥈 Intermediate (your current)

```
diskStorage → stream → ImageKit → delete
```

---

### 🥇 Advanced (industry standard)

```
Frontend → ImageKit directly
Backend → only auth
```

---

## 🧨 12. Key Lessons

* File upload = **streaming problem**, not JSON problem
* Always clean temp files
* Don’t store files in DB
* Understand flow before copying code
* Async mistakes cause silent bugs
